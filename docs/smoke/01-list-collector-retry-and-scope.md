# Smoke Test 01: List Collector (Retry + Scope Guard)

## Что тестируем

Проверяем устойчивость `job_list_collector` к временной ошибке list API и корректную защиту от ложной деактивации вакансий при смене query scope.

## Набор данных

Используется in-memory тестовый набор из `tests/test_job_list_collector_inactive.py`:
- минимальный список вакансий (`A`, `B`);
- фейковая Mongo-коллекция для `stellenangebote`, `stellenangebote_history`, `pipeline_state`;
- фейковые ответы API, включая временный `timeout`.

## Этапы

1. Подготовка in-memory коллекций и fake session.
2. Эмуляция временной ошибки API на первом запросе.
3. Повтор запроса и завершение run.
4. Проверка, что данные обновлены и поведение `scope_changed` корректно.

## Что проверяется

1. Retry действительно выполняется при временной ошибке (`timeout`).
2. Run продолжается после retry и не завершается аварийно.
3. При смене query scope не происходит `list_missing` mass deactivation.

## Что запускается

```bash
.venv/bin/pytest -q tests/test_job_list_collector_inactive.py -k "retry or scope_changed"
```

## Ожидаемый результат

- Все выбранные тесты проходят.
- Нет падения на временной API-ошибке.

## Возможные проблемы и ограничения

1. Это unit-smoke на fake данных, а не интеграционный прогон с реальным API.
2. Не покрывает реальные сетевые задержки/ограничения внешнего сервиса.
3. Не проверяет производительность на больших объемах.
