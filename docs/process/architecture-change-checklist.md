# Чеклист Архитектурных Изменений

## Назначение
Быстрый DoD-чеклист для любых изменений архитектуры, правил ранжирования и контрактов данных.

## 0) До начала
- [ ] Понята причина изменения (проблема/метрика/риск).
- [ ] Определен scope (модули, конфиги, данные).
- [ ] Для крупной задачи есть запись в `PLANS.md`.

## 1) Контракты и совместимость
- [ ] Ясно зафиксировано, что меняется в runtime-контракте.
- [ ] Проверено влияние на CLI/JSON-выход.
- [ ] Есть fallback-поведение на случай недоступности нового компонента.

## 2) Алгоритм и формулы
- [ ] Формулы score и порядок этапов описаны явно.
- [ ] Указаны пороги/веса и где они задаются в конфиге.
- [ ] Для hard-filters указаны обязательные поля и правила отсева.

## 3) Данные и индексы
- [ ] Проверено, нужны ли новые поля/индексы.
- [ ] Описан план миграции или подтверждено, что миграция не нужна.
- [ ] Учет идемпотентности сохранен.

## 4) Производительность
- [ ] Зафиксированы лимиты (`top_k`, `top_n`, batch size, timeout).
- [ ] Оценен риск роста latency/стоимости.
- [ ] Есть метрики “до/после” на фиксированном наборе запросов.

## 5) Качество
- [ ] Обновлены/добавлены тесты (unit/integration по месту).
- [ ] Проверены критичные кейсы и edge-cases.
- [ ] Подтверждено отсутствие регрессии по базовым сценариям.

## 6) Документация и история решений
- [ ] Обновлен актуальный архитектурный документ (`docs/architecture/*`).
- [ ] Добавлен ADR с “старое -> новое -> почему -> риски -> откат”.
- [ ] В worklog зафиксированы результаты прогона/метрик (если применимо).

## 7) Готово к слиянию
- [ ] Изменения разбиты на смысловые коммиты.
- [ ] Открытые вопросы и follow-ups явно перечислены.
- [ ] Текущее состояние репозитория понятно (что в коммитах, что вне).
