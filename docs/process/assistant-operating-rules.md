# Правила Работы Ассистента (Операционный Контракт)

## Цель
Фиксировать повторяемый процесс работы после каждого запроса, чтобы:
- не терялись решения;
- изменения были проверяемыми;
- архитектура и правила оставались синхронизированы с кодом.

## Область действия
- Применяется к любому запросу, где затрагиваются код, конфиги, тесты, архитектура, процессы.
- Не заменяет `AGENTS.md`, а конкретизирует ежедневный рабочий цикл.

## Базовый цикл после каждого запроса
1. Уточнить цель и границы изменений.
2. Проверить, является ли задача “крупной”:
- если да, сначала обновить/добавить запись в `PLANS.md`, потом код.
3. Внести минимально достаточные изменения.
4. Прогнать релевантные проверки (тесты/команды).
5. Обновить документацию, если изменился контракт поведения.
6. Зафиксировать итог:
- что изменено;
- что проверено;
- что осталось открытым.

## Обязательные проверки качества
1. Безопасность:
- секреты не выводить;
- не добавлять креды в репозиторий/логи.
2. Совместимость:
- не ломать текущий CLI/JSON-контракт без явного решения и фиксации в docs.
3. Идемпотентность пайплайнов:
- повторный запуск не должен приводить к лишним записям/действиям.
4. Наблюдаемость:
- итоговые логи должны содержать ключевые счетчики.

## Когда обновлять `PLANS.md`
Обязательно, если:
- меняется архитектура/алгоритм;
- затрагиваются несколько модулей;
- меняется схема данных, индексы или runtime-контракт.

## Когда создавать ADR
Создавать запись в `docs/architecture/adr/` если:
- принято архитектурное решение с компромиссом;
- поменялись правила ранжирования/релевантности/фильтрации;
- есть риск повторного “переобсуждения” решения в будущем.

## Связь “код <-> документация”
Если изменились:
- формулы score,
- порядок этапов pipeline,
- правила filters/gates,
то нужно обновить:
- актуальный документ в `docs/architecture/*`,
- и добавить ADR c причиной изменения.

## Формат отчета по завершению запроса
Кратко и проверяемо:
1. Что сделано.
2. Какие файлы изменены.
3. Какие проверки выполнены.
4. Риски/ограничения.
5. Следующий шаг (если нужен).
