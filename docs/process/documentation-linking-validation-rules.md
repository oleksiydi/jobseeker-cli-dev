# Правила Документации: Ссылки, Перекрёстные Ссылки, Проверка

Audience: `Human + AI`  
Source of truth: `Yes` (стандарт оформления и проверки ссылок в документации)

## Цель
Сделать документацию предсказуемой:
- ссылки внутри `docs/` всегда кликабельны;
- кросс-ссылки не ломаются при публикации;
- Mermaid-диаграммы не дают 404/syntax error из-за путей.

## 1) Базовые правила ссылок

1. Для страниц внутри `docs/` использовать Markdown-ссылки:
- правильно: `[Runtime Contract](../architecture/00-runtime-contract.md)`
- неправильно: `` `docs/architecture/00-runtime-contract.md` `` как единственный способ навигации.

2. Для файлов вне `docs/` (`README.md`, `AGENTS.md`, `PLANS.md`) в контенте сайта:
- писать как текстовый путь в backticks;
- не делать Markdown-ссылкой, чтобы не ломать `mkdocs --strict`.

3. Относительные ссылки в Markdown:
- в обычном тексте использовать относительный путь от текущего файла;
- для ссылок между разделами предпочитать короткие и явные пути.

## 2) Правила для Mermaid `click`

1. В `click` использовать абсолютные URL-пути сайта:
- правильно: `click X "/process/assistant-operating-rules/" "..."`
- неправильно: `click X "assistant-operating-rules/" "..."`

2. Не ссылаться из `click` на файлы вне `docs/`.

3. Для `click` выбирать страницы, реально присутствующие в `mkdocs.yml` nav.

## 3) Правила читаемости

1. В блоках “Связанные документы”:
- сначала название ссылки, потом назначение;
- для ключевых документов добавлять краткое пояснение “зачем читать”.

2. Для индексных страниц (`docs/index.md`, `docs/architecture/README.md`):
- давать кликабельную ссылку + явный путь `docs/...`.

## 4) Обязательная проверка перед завершением

Выполнить:

```bash
.venv/bin/mkdocs build --strict
```

Критерий:
- сборка проходит без warning/error по отсутствующим целям ссылок.

Дополнительно для Mermaid:
1. открыть обновлённую страницу в браузере;
2. проверить 1-2 клика по узлам диаграммы;
3. если 404 — проверить, что путь в `click` начинается с `/`.

## 5) Быстрый чек-лист (DoD)

- [ ] Внутренние документы `docs/*` сделаны Markdown-ссылками.
- [ ] Внешние файлы (вне `docs/`) не оформлены как ссылки сайта.
- [ ] Mermaid `click` использует абсолютные пути `/...`.
- [ ] `mkdocs build --strict` успешно.
- [ ] Для изменённой диаграммы проверен хотя бы один реальный переход в браузере.

## 6) Типовые ошибки и исправления

1. Ошибка: `404` вида `/process/<current-page>/<target>/`  
Причина: относительный путь в `Mermaid click`.  
Исправление: заменить на абсолютный `/process/<target>/`.

2. Ошибка `mkdocs --strict`: target not found среди documentation files  
Причина: ссылка на файл вне `docs/`.  
Исправление: оставить как текстовый путь в backticks.

3. Ошибка `Syntax error in text mermaid version ...`  
Причина: слишком сложная/неподдерживаемая конструкция диаграммы.  
Исправление: упростить подписи/узлы или заменить тип диаграммы на более стабильный (`flowchart`).
