# Эмбеддинги и косинусное расстояние: объяснение с алгоритмами

## 1) Что такое эмбеддинг
**Эмбеддинг** — это числовой вектор, который кодирует смысл текста.

Пример:
- текст: `"Frontend Entwickler React TypeScript"`
- выход модели: вектор вроде `[0.12, -0.04, ..., 0.31]` длины 384/768/1024.

Идея:
- похожие по смыслу тексты -> близкие векторы;
- непохожие тексты -> далекие векторы.

## 2) Что делает embedding-модель
Алгоритмически:
1. Текст токенизируется.
2. Токены проходят через нейросеть-трансформер.
3. Полученные представления агрегируются (pooling).
4. На выходе получается один вектор фиксированной длины.

Это и есть “сжатый смысл” текста в числах.

## 3) Что такое косинусное сходство (cosine similarity)
Для векторов `a` и `b`:

`cos_sim(a,b) = (a · b) / (||a|| * ||b||)`

Где:
- `a · b` — скалярное произведение;
- `||a||` и `||b||` — длины векторов.

Интуиция:
- сравнивается не “длина”, а **угол** между векторами.
- чем меньше угол, тем больше cos_sim (ближе к 1).

Диапазон обычно:
- `1` — очень похоже,
- `0` — почти не связано,
- `<0` — противоположные направления (в практике retrieval редко полезно).

## 4) “Косинусное расстояние” vs “косинусное сходство”
Часто используют:
- `cosine_similarity` (чем больше, тем лучше),
или
- `cosine_distance = 1 - cosine_similarity` (чем меньше, тем лучше).

Важно не путать знак “лучше/хуже”.

## 5) Зачем это в поиске вакансий
1. Строим embedding запроса.
2. Сравниваем с embedding-ами чанков вакансий.
3. Берем top-k по максимальному cosine similarity.

Это дает быстрый semantic retrieval.

## 6) Термины RU -> EN
1. Эмбеддинг -> Embedding
2. Вектор признаков -> Feature vector
3. Косинусное сходство -> Cosine similarity
4. Косинусное расстояние -> Cosine distance
5. Ближайшие соседи -> Nearest neighbors
6. Ранжирование -> Ranking
7. Переранжирование -> Reranking
8. Инференс -> Inference

## 7) Вопрос про языки: русский термин и английский перевод
Обычно (для хороших multilingual-моделей):
- слово/фраза на русском и его корректный перевод на английский
часто оказываются **ближе** друг к другу,
чем к случайным словам из другой области.

Но это не строгий закон, потому что влияет:
1. контекст слова;
2. многозначность;
3. доменная лексика;
4. качество конкретной модели.

Пример:
- RU: “бухгалтерский учет”
- EN: “accounting”
обычно близко.

Но:
- RU: “учет” без контекста может увести к другим значениям.

## 8) Почему embedding не решает всё
Embedding retrieval хорош для “первичного отбора”.
Но финальный порядок может быть неидеальным:
- попадает шум из текста;
- роль может не совпадать строго.

Поэтому нужен второй этап: rerank.
