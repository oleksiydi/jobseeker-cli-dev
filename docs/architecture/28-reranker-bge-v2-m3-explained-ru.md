# BAAI/bge-reranker-v2-m3: объяснение простыми словами (с технической сутью)

## Для чего нужна эта модель
В поиске вакансий есть два шага:
1. **Retrieval**: быстро найти “примерно похожие” вакансии.
2. **Rerank**: точно переставить найденные вакансии в правильном порядке.

`BAAI/bge-reranker-v2-m3` — это модель для шага 2 (rerank).

## Что это за тип модели
- Это **cross-encoder reranker**.
- Она читает **пару текстов вместе**:
  - запрос пользователя;
  - текст кандидата (вакансии).
- И выдает число: насколько хорошо пара подходит друг другу.

Разница с обычным embedding-поиском:
- embedding-поиск сравнивает два отдельных вектора;
- cross-encoder смотрит пару совместно и лучше ловит смысловые связи.

## Что подавать на вход
Минимальный практичный формат:
1. `query`: запрос пользователя.
2. `candidate_text`: компактный текст вакансии.

Обычно `candidate_text` собирают как:
- `title + role + top_chunks`
- опционально: локация/тип занятости.

Важно:
- если в `candidate_text` много мусора (контакты, “подайте заявку”, юридические хвосты),
  модель начинает ранжировать этот шум.

## Что модель отдает на выход
- `model_score` (обычно float): чем выше, тем релевантнее.
- Потом вакансии сортируют по этому score.

## Как это выглядит алгоритмически
1. Есть список кандидатов после retrieval (например, top-50).
2. Для каждого кандидата строим пару `(query, candidate_text)`.
3. Прогоняем пары через reranker.
4. Получаем `model_score` для каждого кандидата.
5. Сортируем кандидатов по убыванию score.

Псевдокод:

```text
candidates = retrieval_top_k(query)
shortlist = take(candidates, top_n)
for c in shortlist:
    c.model_score = reranker(query, build_candidate_text(c))
result = sort_desc(shortlist, by=model_score)
```

## Ограничения модели
1. **Скорость**: медленнее, чем cosine на embedding-векторах.
2. **Стоимость CPU/GPU**: заметно выше, особенно при большом `top_n`.
3. **Чувствительность к формату входа**: плохой шаблон текста ухудшает качество.
4. **Языковые эффекты**: мультиязычность есть, но домен и формулировки сильно влияют.

## Насколько повышает точность
Точного “магического процента” нет, потому что зависит от:
- домена вакансий,
- качества данных,
- качества candidate_text,
- размера rerank shortlist (`top_n`),
- baseline ранжирования.

На практике чаще всего:
- снижается число явных нерелевантных вакансий в top-20;
- улучшается порядок “похожих” вакансий.

Но это нужно подтверждать benchmark-ом “до/после” на фиксированном наборе запросов.

## За счет каких алгоритмических идей становится лучше
1. **Joint encoding** пары текстов: модель видит вопрос и вакансию вместе.
2. **Context-aware scoring**: учитывается контекст слов, а не только пересечение токенов.
3. **Нелинейные зависимости**: модель ловит соответствия уровня “навык ↔ роль”, даже при разных формулировках.

Итог:
- retrieval дает скорость и охват;
- reranker добавляет точность в финальном ранжировании.
